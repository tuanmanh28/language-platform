# BE-09 — Private content store and owner-only access

- **Type / branch:** `feat` / `feat/private-content`
- **Lane:** be
- **Depends on:** BE-03, BE-04, BE-08
- **Verify:** `./gradlew spotlessCheck :core:model:jvmTest :core:exam-engine:jvmTest :backend:test`

## Goal
The owner's own IELTS material (bought books, official samples) is stored and served privately, never from the public repo.

## Scope
- Config `CONTENT_DIR` (default `~/LanguagePlatform/content`, outside the repo) with `reading/`, `listening/`, `writing/`, `audio/` sub-folders. Document it in `backend/README` and `.env.example`.
- Seeding reads `content/` (original public samples, `visibility = public`) and `CONTENT_DIR` (`visibility = private`). New migration adds `visibility` to the content tables.
- Private content is returned only to owners: config `OWNER_EMAILS` (comma-separated) checked against the authenticated user from BE-04; everyone else gets 404 for private ids and never sees them in lists.
- `TokenVerifier` gets a `DevTokenVerifier` enabled only when `APP_ENV=dev` (fixed token → owner user) so the app can be used locally without Firebase. Refuse to start with it in `prod`.
- Audio: `AudioStorage` interface; `LocalAudioStorage` streams files from `CONTENT_DIR/audio` through an authenticated endpoint (dev), `R2AudioStorage` returns short-lived presigned URLs (S3-compatible API; credentials from env, only needed at runtime). Listening API returns URLs from the active storage.
- Add `CONTENT_DIR` and `*.mp3`/`*.pdf` safety patterns to `.gitignore` as a second line of defence.

## Rules
- Real IELTS/Cambridge material never enters git, tests, fixtures, logs or commit messages. Tests use small original fixtures you write yourself.
- No secret is needed to finish: anything that talks to an external service sits behind an interface with a fake used in tests.

## Out of scope
Import tooling (BE-11), new content types.

## Acceptance criteria
- Tests: anonymous and non-owner users never see private tests (list, detail, submit, audio); owner sees both; dev verifier rejected in prod config.
- Seeding the same `CONTENT_DIR` twice is idempotent.
