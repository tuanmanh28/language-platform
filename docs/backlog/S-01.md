# S-01 — Formatting and lint tooling

- **Type / branch:** `build` / `build/code-style-tooling`
- **Lane:** core
- **Depends on:** U-01
- **Verify:** `./gradlew spotlessCheck :core:model:jvmTest :core:exam-engine:jvmTest :shared:jvmTest :backend:test :app-android:assembleDebug`

## Goal
The conventions in the `code-conventions` skill are enforced by tools, locally and in CI, so neither agents nor the
reviewer spend time on formatting.

## Scope
- Spotless Gradle plugin with ktlint (latest stable of both, looked up per `gradle-dependency`) applied to every Kotlin
  module and `*.gradle.kts`, reading `.editorconfig`. Reference: `_reference/nowinandroid/build-logic/` and
  `_reference/nowinandroid/gradle/libs.versions.toml` (`spotless`, `ktlint`).
- Compose rules for ktlint (`io.nlopez.compose.rules:ktlint`, latest stable) on `ui-compose`.
- Configure it once in the root build (or a `build-logic` convention plugin if that is simpler); exclude `build/`,
  generated sources and `_reference/`.
- `swift-format` config `app-apple/.swift-format` (4 spaces, line length 120) and a `scripts/format-swift.sh` that runs
  `xcrun swift-format format --in-place --recursive app-apple/Sources`.
- Run `./gradlew spotlessApply` once and commit the reformatting as part of this task.
- CI: a `spotlessCheck` step in the `jvm-android` job and `xcrun swift-format lint --strict --recursive app-apple/Sources`
  in the `apple` job.
- Tune `.editorconfig` only where a ktlint rule conflicts with Compose or the skills; explain each change in the summary.

## Out of scope
Behaviour changes, renames (R-01 does them), detekt.

## Acceptance criteria
- `./gradlew spotlessCheck` passes on a clean checkout; CI runs it.
- Running `spotlessApply` twice produces no diff.

## Definition of done
- Verify command passes and the code review approves.
- Committed on branch `build/code-style-tooling` as `build: <summary>` (no task id in the message).
