# BE-01 — Backend configuration, environments and observability

- **Type / branch:** `feat` / `feat/be-01-backend-config`
- **Lane:** be
- **Depends on:** F-01
- **Verify:** `./gradlew :backend:test`

## Goal
Make the backend configurable per environment and easy to debug in production.

## Scope
- Typed config loaded from environment variables with sensible local defaults: `PORT`, `APP_ENV` (`local|staging|prod`), `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`, `CORS_ALLOWED_ORIGINS` (comma separated; `*` only when `APP_ENV=local`). Put it in an `AppConfig` data class; no secrets in code.
- `GET /health` returns `{status, version, env}`; version comes from the Gradle project version embedded at build time.
- JSON structured logging in non-local envs (logback encoder), request id per call (Ktor `CallId` plugin) included in logs and the `X-Request-Id` response header.
- Graceful shutdown hook.
- Update `docker-compose.yml` env vars and README if names change.

## Acceptance criteria
- Tests cover config parsing (defaults, overrides, invalid values) and the health payload.
- CORS honours `CORS_ALLOWED_ORIGINS` (test with an allowed and a disallowed origin).
