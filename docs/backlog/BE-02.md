# BE-02 — PostgreSQL with Flyway, Exposed and Testcontainers

- **Type / branch:** `feat` / `feat/postgres-flyway`
- **Lane:** be
- **Depends on:** BE-01
- **Verify:** `./gradlew :backend:test`

## Goal
Give the backend a real database layer.

## Decisions (do not change)
- PostgreSQL 17, HikariCP, **Flyway** migrations in `backend/src/main/resources/db/migration`, **Exposed** (DSL, not DAO, `org.jetbrains.exposed.v1.*`, `suspendTransaction`) for queries — follow the `backend-database` skill. All libraries at their latest stable version.
- Integration tests use **Testcontainers** (`postgres:17`). Tests that need Docker must be skipped with a clear message when Docker is unavailable.

## Scope
- `Database` module: create pool from `AppConfig`, run Flyway on startup, expose a `suspend fun <T> tx(block)` helper on `Dispatchers.IO`.
- `V1__init.sql`: tables `reading_tests (id text pk, module text, title text, time_limit_minutes int, content jsonb, version int, published boolean, updated_at timestamptz)`, `users (id uuid pk, firebase_uid text unique, email text, display_name text, created_at timestamptz)`, `reading_attempts (id uuid pk, user_id uuid fk, test_id text fk, correct_count int, total_questions int, band numeric(2,1), answers jsonb, created_at timestamptz)` with sensible indexes.
- `/health` reports database reachability.

## Acceptance criteria
- Integration test starts Postgres via Testcontainers, runs migrations and does a round trip insert/select.
- App still starts with `./gradlew :backend:run` against `docker compose up db`.
