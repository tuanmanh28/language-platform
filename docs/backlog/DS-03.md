# DS-03 — Reading and Listening test room, results and review

- **Type / branch:** `docs` / `docs/design-test-room-and-review`
- **Lane:** design
- **Depends on:** DS-01
- **Verify:** `test -s docs/design/test-room/README.md && ls docs/design/test-room/mockups/*.html`
- **Reviews:** design-reviewer

## Goal
Taking a test feels like the real IELTS on computer; reviewing it teaches clearly.

## Scope
- Library: browse Cambridge books → tests → skills, filters (done, not done, score), resume.
- Exam mode (faithful to IELTS on computer): split passage/questions, highlight, notes, timer, question navigator, flag, audio controls rules for Listening; phone layout with a passage/questions switcher.
- Practice mode differences; submit flow and confirmation.
- Results: band, score per section and question type, time used; celebration that stays calm.
- Answer review: filters, evidence highlighting in passage/transcript, paraphrase pairs, trap, save words, jump to intensive listening; accuracy by question type with tips.
- Deliverables: `docs/design/test-room/README.md` and `docs/design/test-room/mockups/*.html` as described in the `ux-design` skill.

## Rules
- Follow the `ux-design` skill: Apple-quality bar — beautiful, simple, friendly, calm, smooth motion.
- Design only: no app code changes. Mockups are self-contained HTML using our tokens.
- Original work: no copied screenshots or assets from other apps; reference them by link.

## Out of scope
Implementation (AND-04, AND-08, AND-09, AND-10).

## Acceptance criteria
- Every screen has all states, Vietnamese copy, accessibility notes and its motion spec.
- Mockups open in a browser with light/dark and phone/desktop frames.

## Definition of done
- Verify command passes and every review approves.
- Follows `CLAUDE.md` and the skills.
- Committed on branch `docs/design-test-room-and-review` as `docs: <summary>` (no task id in the message).
