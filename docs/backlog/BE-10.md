# BE-10 — Detailed explanations, evidence and paraphrases per question

- **Type / branch:** `feat` / `feat/question-explanations`
- **Lane:** be
- **Depends on:** BE-08
- **Verify:** `./gradlew spotlessCheck :core:model:jvmTest :core:exam-engine:jvmTest :backend:test`

## Goal
Every question can carry a full explanation so a wrong answer teaches something.

## Scope
- `core/model`: replace the plain `explanation` with `Explanation(text: String, evidence: Evidence?, paraphrases: List<Paraphrase>, trap: String?)`. `Evidence` is a sealed type: `PassageEvidence(paragraphId, quote)` for Reading, `TranscriptEvidence(sectionNumber, startSeconds, endSeconds, quote)` for Listening. `Paraphrase(inQuestion, inSource)`. `trap` explains the distractor learners usually pick.
- `Explanation.text` and `trap` are Vietnamese; `quote` and paraphrases stay in English exactly as in the source.
- Keep reading old content: a custom serializer or migration step accepts the old string form.
- Update both JSON schemas and the original samples with full explanations for every question.
- Backend returns explanations only in the submit result (`QuestionResult`), never in the test payload, so answers are not leaked before submitting.

## Rules
- Real IELTS/Cambridge material never enters git, tests, fixtures, logs or commit messages. Tests use small original fixtures you write yourself.
- No secret is needed to finish: anything that talks to an external service sits behind an interface with a fake used in tests.

## Out of scope
UI (AND-09).

## Acceptance criteria
- Schema/sample consistency tests extended; a test proves `GET` test payloads contain no explanations or answers.
- Old-format content still deserializes.

## Definition of done
- Verify command passes and the code review approves.
- Follows `CLAUDE.md` and the skills.
- Committed on branch `feat/question-explanations` as `feat: <summary>` (no task id in the message).
