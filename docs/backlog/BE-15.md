# BE-15 — Detailed AI grading for Writing

- **Type / branch:** `feat` / `feat/writing-grading`
- **Lane:** be
- **Depends on:** BE-14
- **Verify:** `./gradlew spotlessCheck :core:model:jvmTest :core:exam-engine:jvmTest :backend:test`

## Goal
Every essay gets examiner-style, fully detailed feedback.

## Scope
- `core/model` `WritingFeedback`: per criterion (Task Achievement/Response, Coherence and Cohesion, Lexical Resource, Grammatical Range and Accuracy) a band (0–9 in 0.5) with strengths, weaknesses and the descriptor-level reason; overall band; inline `Annotation(start, end, category, severity, original, correction, explanationVi)`; feedback per paragraph; `VocabularyUpgrade(original, better, why)`; a rewritten version at band 7.5–8 keeping the learner's ideas; task checks (word count under minimum, Task 1 overview present, Task 2 position clear); 3 priorities for the next essay.
- `core/exam-engine`: overall Writing band = mean of the four criteria rounded down to the nearest 0.5 as IELTS does, and Task 1/Task 2 weighting (Task 2 counts double) when both exist. Exhaustive tests.
- `ScoringProvider` interface; `ClaudeScoringProvider` using the official Anthropic Java/Kotlin SDK (latest stable), model from `GRADING_MODEL` (default: the latest Claude Opus model, looked up), structured JSON output validated against `WritingFeedback`; the grading prompt contains our own summary of the public IELTS band descriptors (not copied verbatim) and asks for Vietnamese explanations.
- Async job: `grading_jobs` table, a coroutine worker with retry and backoff, idempotent per submission; status visible through BE-14 endpoints; feedback stored as JSON.
- `ANTHROPIC_API_KEY` only needed at runtime; without it the worker marks jobs `FAILED` with a clear reason. Tests use a fake provider and a golden test for the prompt.

## Rules
- Real IELTS/Cambridge material never enters git, tests, fixtures, logs or commit messages. Tests use small original fixtures you write yourself.
- No secret is needed to finish: anything that talks to an external service sits behind an interface with a fake used in tests.

## Out of scope
Calibration (BE-16), Speaking.

## Acceptance criteria
- Tests: band rounding, job lifecycle (success, provider error → retry → failure), invalid model output rejected, annotations within text bounds.

## Definition of done
- Verify command passes and the code review approves.
- Follows `CLAUDE.md` and the skills.
- Committed on branch `feat/writing-grading` as `feat: <summary>` (no task id in the message).
