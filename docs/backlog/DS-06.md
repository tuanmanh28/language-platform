# DS-06 — Writing room and feedback

- **Type / branch:** `docs` / `docs/design-writing`
- **Lane:** design
- **Depends on:** DS-01
- **Verify:** `test -s docs/design/writing/README.md && ls docs/design/writing/mockups/*.html`
- **Reviews:** design-reviewer

## Goal
Writing an essay and reading its feedback is focused and genuinely instructive.

## Scope
- Prompt library, writing room (timer, word count, distraction-free editor, Task 1 chart view).
- Grading wait state; feedback overview with criterion bands; annotated essay; sentence-by-sentence mode; strengths and habits; upgraded version with diff; history chart.
- How corrections and upgrades become flashcards.
- Deliverables: `docs/design/writing/README.md` and `docs/design/writing/mockups/*.html` as described in the `ux-design` skill.

## Rules
- Follow the `ux-design` skill: Apple-quality bar — beautiful, simple, friendly, calm, smooth motion.
- Design only: no app code changes. Mockups are self-contained HTML using our tokens.
- Original work: no copied screenshots or assets from other apps; reference them by link.

## Out of scope
Implementation (AND-11, AND-12).

## Acceptance criteria
- Every screen has all states, Vietnamese copy, accessibility notes and its motion spec.
- Mockups open in a browser with light/dark and phone/desktop frames.

## Definition of done
- Verify command passes and every review approves.
- Follows `CLAUDE.md` and the skills.
- Committed on branch `docs/design-writing` as `docs: <summary>` (no task id in the message).
