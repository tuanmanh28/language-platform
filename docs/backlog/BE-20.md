# BE-20 — Unattended import runner for the whole library

- **Type / branch:** `feat` / `feat/content-import-runner`
- **Lane:** be
- **Depends on:** BE-12, BE-17, BE-19, BE-14
- **Verify:** `./gradlew spotlessCheck :core:model:jvmTest :backend:test :tools:content-import:test`

## Goal
Import every test of every book overnight with full explanations, resumable and safe, without touching the repository.

## Scope
- `scripts/content/import-library.py` (stdlib Python, like the orchestrator): work units = (book, test, Listening | Reading | Writing | Speaking); each unit runs `claude -p` in `CONTENT_DIR` with the `ielts-content-import` skill, allowed tools limited to reading `CONTENT_DIR`, writing `CONTENT_DIR/tests`, and the `tools/content-import` commands.
- Each unit: structure questions and answers from the classified pages and answer key → write the BE-10 explanation for every question (Vietnamese, evidence quote, paraphrases, trap) → `validate` until clean (max 3 attempts) → `align` for Listening → mark done. Writing units store the prompt (with cropped figure) and every sample answer with examiner band and comment into `CONTENT_DIR/calibration/`; Speaking units store Part 1–3 prompts for Phase 4.
- State in `CONTENT_DIR/import-state.json`: pending, running, done, failed (with reason), needs-review (validation warnings, low OCR or alignment confidence). Commands: `status`, `run [--books 21,20] [--parallel 2]`, `retry`, `report`.
- Order: newest books first (21 → 1). Waits and resumes when the Claude usage limit is hit, like the orchestrator.
- `seed` after each finished book so tests appear in the app as soon as they are ready.
- Never writes into the repository and never commits; refuses to run if `CONTENT_DIR` is inside a git work tree.

## Rules
- Real IELTS/Cambridge material never enters git, tests, fixtures, logs or commit messages. Tests use small original fixtures you write yourself (generated PDFs, synthetic audio tones, invented file names).
- No secret is needed to finish: external binaries (tesseract, ffmpeg, unar, whisper-cli, claude) sit behind interfaces with fakes in tests and give an install hint when missing.
- Everything the tools write goes under `CONTENT_DIR`; refuse paths inside the repository.

## Out of scope
The content itself (it stays in `CONTENT_DIR`).

## Acceptance criteria
- Tests with a fake `claude` and fake tools: unit ordering, resume after interruption, failure and retry, usage-limit wait, repo-path refusal.

## Definition of done
- Verify command passes and the code review approves.
- Follows `CLAUDE.md` and the skills.
- Committed on branch `feat/content-import-runner` as `feat: <summary>` (no task id in the message).
