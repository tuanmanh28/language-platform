# R-01 — Align existing code with the skills

- **Type / branch:** `refactor` / `refactor/align-with-skills`
- **Lane:** core
- **Depends on:** S-02
- **Verify:** `./gradlew spotlessCheck :core:model:jvmTest :core:exam-engine:jvmTest :shared:jvmTest :backend:test :app-android:assembleDebug :app-desktop:compileKotlin :shared:compileKotlinIosSimulatorArm64`

## Goal
The Phase 1 scaffold becomes the reference implementation every later task copies: clean, simple, following every skill.

## Scope
- **Errors (`error-handling`):** add kotlin-result + kotlin-result-coroutines (latest stable, `api` from `core/model`). `ReadingError` sealed interface; `ReadingApi` and `ReadingRepository` return `Result`; ViewModels fold with `mapBoth`; backend routes map `ReadingError.toHttp()`; replace the custom exceptions.
- **Data layer (`shared-data-layer`):** `ReadingRepository` becomes an interface + `OfflineFirstReadingRepository` with a small DAO wrapper over SQLDelight; base URL via Ktor `DefaultRequest`.
- **ViewModels (`kmp-feature`):** derive state with `stateIn` where it fits; inject `Clock` for the timer.
- **Swift (`swiftui-interop`):** replace `ViewModelHolder` with the `ViewModelOwner` + `.task`/`for await`/`clear()` pattern; content views get `#Preview`s.
- **Compose (`compose-screen`):** stateful/stateless split, user-facing strings into Compose resources, previews per state.
- **Backend (`backend-endpoint`):** route → service → content store layering, `plugins/` and `config/` packages.
- **Tests (`testing`):** Turbine for ViewModel tests, fakes for repository/API, `MockEngine` test for `ReadingApi`.
- **Naming (`code-conventions`):** move files into feature-first packages (`shared/…/reading/data/`), rename anything that breaks the naming tables (`Utils`, `Impl`, layer-first packages), string keys `<feature>_<screen>_<meaning>`.
- **Comments:** remove every comment that restates code or narrates; keep only short English "why" comments.

## Out of scope
New features, navigation (AND-03), design tokens (AND-01), database (BE-02).

## Acceptance criteria
- No `runCatching` in suspend code, no `Result` in Swift-facing API, no hard-coded UI strings, no narrating comments.
- App behaviour unchanged (Reading list → test → result, offline fallback).

## Definition of done
- Verify command passes and the code review approves.
- Committed on branch `refactor/align-with-skills` as `refactor: <summary>` (no task id in the message).
