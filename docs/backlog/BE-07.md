# BE-07 — Deploy pipeline: Cloud Run + Neon

- **Type / branch:** `feat` / `feat/deploy-cloud-run`
- **Lane:** be
- **Depends on:** BE-02
- **Verify:** `./gradlew :backend:test`

## Goal
One-command (or on-push) deploy of the backend to Google Cloud Run, using Neon for Postgres.

## Scope
- Multi-stage Dockerfile option that builds only `:backend` (configure Gradle so `-PbackendOnly` skips Android modules), keeping the current jar-based Dockerfile working.
- GitHub Actions workflow `deploy-backend.yml` (manual dispatch + push to `main` touching `backend/**` or `core/**`): build image, push to Artifact Registry, deploy to Cloud Run, run Flyway on start. Authentication via Workload Identity Federation; all ids/secrets as GitHub secrets/vars, documented.
- `docs/deploy.md`: step-by-step setup for GCP project, Artifact Registry, Cloud Run service (min instances 0, region asia-southeast1), Neon database, secrets, and a budget alert.

## Out of scope
Actually creating cloud resources (the owner does it following the doc).

## Acceptance criteria
- `docker build` of the multi-stage image works locally (report result if Docker is available).
- Workflow passes `actionlint` if available.

## Definition of done
- Verify command passes.
- Follows `CLAUDE.md` (scope, architecture, tests, no AI attribution in commits).
- Committed on branch `feat/deploy-cloud-run` as `feat: <summary>` (no task id in the message).
