# DS-04 — Intensive listening and dictation

- **Type / branch:** `docs` / `docs/design-listening-study`
- **Lane:** design
- **Depends on:** DS-01
- **Verify:** `test -s docs/design/listening-study/README.md && ls docs/design/listening-study/mockups/*.html`
- **Reviews:** design-reviewer

## Goal
Re-listening and dictation feel as smooth as a great podcast player.

## Scope
- Intensive listening: section/sentence navigation, A–B loop, repeat, speed, synced karaoke transcript, hide transcript, evidence playback.
- Dictation like Study4: typing area, word-level feedback colours, hints, scoring, keyboard shortcuts on desktop, session summary.
- Player component specs (mini player, full player, waveform/progress) and their transitions.
- Deliverables: `docs/design/listening-study/README.md` and `docs/design/listening-study/mockups/*.html` as described in the `ux-design` skill.

## Rules
- Follow the `ux-design` skill: Apple-quality bar — beautiful, simple, friendly, calm, smooth motion.
- Design only: no app code changes. Mockups are self-contained HTML using our tokens.
- Original work: no copied screenshots or assets from other apps; reference them by link.

## Out of scope
Implementation (AND-13, AND-14).

## Acceptance criteria
- Every screen has all states, Vietnamese copy, accessibility notes and its motion spec.
- Mockups open in a browser with light/dark and phone/desktop frames.

## Definition of done
- Verify command passes and every review approves.
- Follows `CLAUDE.md` and the skills.
- Committed on branch `docs/design-listening-study` as `docs: <summary>` (no task id in the message).
